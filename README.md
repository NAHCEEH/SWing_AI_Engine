# SWing AI Engine

팀 SWing의 **TeamFit 팀 편성 엔진과 FastAPI 백엔드**를 담은 저장소입니다. DS 창업캡스톤디자인 프로젝트로, 학생 설문과 교수의 편성 조건을 반영해 수업별 팀을 구성합니다.

TeamFit은 학생의 희망 역할, 가용 시간, 협업 성향과 전공 정보를 함께 평가합니다. 팀별 조화도를 계산하고 학생 배치를 개선해, 전체 팀의 평균 점수와 가장 낮은 팀의 점수를 함께 높이는 편성을 탐색합니다.

엔진은 팀 점수 함수, 조합 최적화, 규칙 기반 교수 메모 해석기로 구성됩니다.

## 주요 기능

- **학생·수업 관리**: 학생·교수 인증, 수업 생성 및 참여, 수강생 조회
- **설문 수집**: 수업별 희망 역할, 스킬, 작업 성향, 가용 시간 저장
- **조건 사전 점검**: 팀 편성 전 조건 충족 가능 여부 확인 및 완화안 안내
- **자동 팀 편성**: 전공, 역할, 시간, 성향과 교수의 제약 조건을 반영한 매칭
- **결과 분석**: 팀 점수, 역할 배정, 조건 충족 여부, 팀별 설명 및 대안 편성 계산
- **엔진 시연**: 데이터베이스 없이 합성 수강생 데이터로 편성 과정 확인

결과 분석 기능의 API 노출 범위와 요청·응답 형식은 백엔드 API 문서에서 확인할 수 있습니다.

## 빠른 시작

Python이 설치된 환경에서 저장소를 내려받습니다.

```bash
git clone https://github.com/NAHCEEH/SWing_AI_Engine.git
cd SWing_AI_Engine/backend
```

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### Windows / PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

### 테스트 및 시연

가상환경을 활성화한 상태에서 `backend/` 폴더 안에서 실행합니다. 엔진 단위 테스트와 시연에는 실행 중인 데이터베이스와 `.env`가 필요하지 않습니다.

```bash
python -m pytest -q
python scripts/engine_demo.py
```

기본 시연은 합성 수강생 45명과 교수 메모를 사용합니다. 사전 점검, 편성, 조건 검산, 팀별 요약과 역할 배정, 재평가 결과를 출력합니다.

```bash
python scripts/engine_demo.py --n 90
python scripts/engine_demo.py --no-note
```

`--n`은 수강생 수를 지정하고, `--no-note`는 교수 메모 없이 실행합니다.

백엔드 서버를 실행하려면 PostgreSQL과 환경변수 설정이 필요합니다. 자세한 절차는 [백엔드 README](backend/README.md)를 참고하세요.

## TeamFit 엔진 동작

```mermaid
flowchart LR
    A[학생 설문과 교수 조건] --> B[메모 해석 및 사전 점검]
    B --> C[초기 팀 배치]
    C --> D[국소 탐색 및 담금질]
    D --> E[여러 시작점의 결과 비교]
    E --> F[팀 편성 및 결과 설명]
```

1. **메모 해석 및 사전 점검**: 교수 메모를 조건으로 변환하고, 학과별 인원 제한과 역할별 최소 인원 등 요청을 충족할 수 있는지 확인합니다.
2. **초기 배치**: 같은 팀에 고정할 학생을 묶고, 희소한 조건을 가진 학생부터 배정합니다.
3. **배치 개선**: 팀 간 학생 교환과 이동으로 점수를 개선합니다. 담금질 탐색은 점수가 일시적으로 낮아지는 교환도 확률적으로 허용해 다른 배치를 탐색합니다.
4. **결과 선택**: 여러 시작점에서 탐색한 결과를 비교해 목적함수가 가장 높은 편성을 선택합니다.
5. **결과 설명**: 팀 구성, 역할 배정, 점수, 조건 충족 여부와 대안을 계산합니다.

### 팀 점수와 최적화 목표

팀 점수는 다음 네 항목에 교수의 가중치를 적용해 0~100점으로 계산합니다.

| 평가 항목 | 내용 |
| --- | --- |
| 전공 | 팀 내 전공 다양성 |
| 역할 | 서로 다른 역할의 배정과 희망 순위 충족도. 1지망 1.0, 2지망 0.6, 3지망 이하 0.3 |
| 시간 | 팀원 모두가 참여할 수 있는 공통 시간. 주 6시간 기준 만점 |
| 성향 | 작업 페이스, 의사결정, 소통 빈도의 유사성과 주도적인 학생의 유무 |

```text
팀 점수 = 100 × Σ(가중치 × 하위 점수) / Σ가중치
목적함수 J = 평균 팀 점수 + 최저 팀 점수 − 1000 × 하드 조건 위반 수
```

하드 조건은 같은 학과의 최대 인원, 특정 학생의 분리·고정, 팀별 역할 최소 인원, 학년 분산 등을 포함합니다.

TeamFit 엔진의 내부 구현은 v1.1이며, API는 `/api/classes/{class_id}/precheck`와 `/api/classes/{class_id}/match-v2` 경로로 제공합니다. 기존 그리디 엔진은 `/api/classes/{class_id}/match`에서 사용합니다.

## 사용한 알고리즘 및 처리 기법

팀 편성에는 학생 배치, 역할 배정, 시간 계산, 제약 조건 검사가 함께 필요합니다. 좋은 편성을 빠르게 찾기 위해 다음 알고리즘과 처리 기법을 조합합니다. 코드 위치는 `backend/app/engine/`를 기준으로 표시했습니다.

| 단계 | 알고리즘·기법 | 엔진에서 하는 일 | 코드 위치 |
| --- | --- | --- | --- |
| 사전 점검 | 개수 기반 필요조건 검사 | 학과 상한, 최소 인원, 태그, 학생 쌍 조건을 검사해 충족 불가능한 요청을 거르고 완화안(`fix`)을 제시 | `precheck.precheck` |
| 사전 점검 | 팀 크기 배분 | 팀 수를 `floor(n / team_size)`로 계산하고 남는 학생을 앞 팀부터 추가 배정. 46명·기준 4명은 5명 팀 2개와 4명 팀 9개로 편성 | `precheck.team_sizes` |
| 채점 | 가중합 다기준 점수 | 전공·역할·시간·성향 하위 점수에 교수 가중치를 적용해 0~100점으로 계산 | `constraints.combine`, `scoring.Evaluator.fit` |
| 채점 | 비트마스크 동적 계획법 | 서로 다른 역할을 배정하면서 학생들의 희망 역할 점수 합을 최대화 | `constraints.best_roles`, `scoring.Evaluator._role` |
| 채점 | 비트마스크 교집합(AND) | 팀원 모두가 가능한 시간 블록을 계산 | `scoring.Evaluator.common_mask` |
| 목표 | 평균·최저 점수 목적함수와 벌점법 | 평균과 최저 팀 점수를 함께 높이고 하드 조건 위반마다 1000점의 벌점 적용 | `constraints.objective`, `scoring.Evaluator.j_value` |
| 초기 배치 | Union-Find | 같은 팀으로 고정할 학생들을 하나의 묶음으로 처리 | `optimizer._units`, `precheck._groups` |
| 초기 배치 | 희소 조건 우선 그리디 | 발표·개발 등 희소한 조건을 가진 학생부터 팀 점수가 크게 개선되는 곳에 배치 | `optimizer.greedy_init` |
| 개선 | 국소 탐색(2-교환 힐클라이밍) | 팀 간 학생 교환 또는 1명 이동으로 목적함수가 개선되면 채택 | `optimizer.local_search` |
| 개선 | 담금질 기법(Simulated Annealing) | 학생 수 × 400회 탐색, 온도 1.5 → 0.02. 점수가 낮아지는 교환도 확률적으로 허용하며 교환의 30%는 최저 팀에서 선택 | `optimizer.anneal` |
| 개선 | 다중 시작(Multi-start) | 기본 3개 시작점에서 탐색해 최고 목적함수의 편성을 선택하고 나머지를 대안으로 제시. 같은 시드로 결과 재현 | `optimizer.optimize` |
| 속도 | 차분 평가와 메모이제이션 | 교환으로 바뀐 두 팀만 재채점하고 팀 점수를 캐시. 하위 3개 팀을 유지해 최저 점수 갱신 | `scoring.Evaluator.team`, `optimizer._State.try_pair` |
| 메모 해석 | 규칙 기반 패턴 매칭(정규식) | 교수 메모를 최소 인원, 분산, 가중치 조건으로 변환 | `nl_rules.parse_requirements` |

알고리즘별 구현과 세부 계산식은 [엔진 README](backend/app/engine/README.md)를 참고하세요.

## 실험 결과

아래 수치는 기존 프로젝트 실험 기록에 따른 합성 데이터 결과입니다. 실제 설문 데이터에 대한 검증은 아직 진행하지 않았습니다.

### 이전 엔진과 비교

합성 수강생 45명과 다음 조건을 기준으로 비교했습니다.

- 같은 학과 학생은 팀마다 최대 2명
- 각 팀에 발표·개발 희망자 각각 1명 이상
- 4학년 학생을 고르게 분산
- 특정 학생 1쌍을 서로 다른 팀으로 분리

| 비교 항목 | 이전 엔진(v2) | TeamFit 엔진 v1.1 |
| --- | --- | --- |
| 사전 점검 | `개발` 태그를 0명으로 처리해 HTTP 422 오류 | 조건 충족 가능 판정 |
| 계산 시간(맥북) | 17.4초 | 0.6초 |
| 팀별 4학년 최대 인원(목표 상한 2명) | 3명 | 2명 |
| 하드 조건 위반 | 11건 | 0건 |
| 단위 테스트 통과 | 17개 | 34개(신규 17개 포함) |

사전 점검 판정과 편성 성능은 실험 기록의 별도 항목입니다. 이전 엔진은 사전 점검에서 실패하므로, 계산 시간과 편성 결과를 두 API의 정상 호출 전체에 대한 비교로 해석하지 않습니다.

### 학생 수에 따른 계산 시간

다음은 클라우드 환경의 실험 기록입니다. 위 맥북 실험과 실행 환경이 다르며, 계산 시간은 실행 환경과 조건에 따라 달라질 수 있습니다.

| 학생 수 | 계산 시간 및 종료 조건 |
| ---: | --- |
| 90명 | 5.0초 |
| 200명 | 16.5초 |
| 300명 | 전체 계산 시간 상한인 20초에 도달해 탐색 종료 |

### 초기 배치와 전체 탐색 비교

합성 수업 20개 중 조건 충족이 가능한 19개를 대상으로, 초기 배치만 수행한 경우와 전체 최적화를 수행한 경우를 비교했습니다.

| 비교 항목 | 초기 배치만 수행 | 전체 최적화 수행 |
| --- | ---: | ---: |
| 하드 조건을 모두 충족한 수업 수 | 4 / 19 | 19 / 19 |

전체 최적화의 점수 요약은 평균 84.3점, 최저 79.8점으로 기록되었습니다.
